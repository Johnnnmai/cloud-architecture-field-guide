# From Consultant to Solutions Architect

Consultants follow a natural path into solutions architecture. The SA role is advisory at its core - understanding client needs, designing solutions, and communicating recommendations. You already do this. The shift is from business-level consulting to technical architecture consulting. You need to build deep cloud platform knowledge and technical credibility.

## What You Already Have

- Structured problem-solving and frameworks
- Client management and stakeholder communication
- Presentation and workshop facilitation
- Requirements gathering and discovery
- Business case development and ROI analysis
- Cross-functional project management
- Executive presence and persuasion

## What You Need to Learn

### Cloud Platform Fundamentals

Two paths to choose from:

Path One: AWS (recommended to start here - largest job market)
- Core services: EC2, S3, RDS, Lambda, VPC, IAM
- Architecture patterns: multi-tier, serverless, event-driven
- AWS Solutions Architect Associate certification
- Pros: largest SA job market, most interview resources
- Fit: those targeting cloud provider SA roles or enterprise companies

Path Two: Azure (strongly recommended if targeting Microsoft ecosystem)
- Core services: VMs, Blob Storage, SQL Database, Functions, VNets, Entra ID
- Architecture patterns: hybrid cloud, Active Directory integration
- Azure Solutions Architect Expert certification
- Pros: strong demand in enterprise and government sectors
- Fit: those with existing Microsoft experience or targeting enterprise clients

If you have time, learn both. Start with one platform deeply, then add the other for breadth.

### System Design

- Architecture patterns - multi-region, high availability, disaster recovery
- Database selection - relational vs NoSQL, when to use each
- Scalability patterns - horizontal scaling, caching, load balancing
- Infrastructure as Code - Terraform basics, enough to understand and discuss

### Security Architecture

- IAM and identity management - least privilege, federation, MFA
- Network security - VPC design, segmentation, encryption
- Compliance frameworks - SOC 2, HIPAA, PCI-DSS mapped to cloud services

### Migration Strategy

- Application portfolio assessment methodologies
- The 7 Rs of migration and when to apply each
- Data migration patterns and validation approaches
- Organizational change management for cloud adoption


## Why This Transition Works

The consulting skill set - client management, structured problem-solving, executive communication - is exactly what separates good SAs from great ones. Many technically strong SAs struggle with the advisory side: understanding what the client actually needs vs what they are asking for, managing expectations, and communicating trade-offs to non-technical executives.

You can step into an SA role by pairing your consulting skills with cloud platform knowledge. The learning curve is primarily technical - you need to build hands-on cloud experience. But the client-facing, communication, and advisory skills that take other SA candidates years to develop are already in your toolkit.


## Suggested Path

1. Learn a cloud platform - pick AWS or Azure, complete the Associate/Expert certification
2. Build hands-on projects - deploy a multi-tier application, create a VPC with proper security, set up monitoring
3. Study architecture design patterns - Well-Architected Framework, reference architectures, real case studies
4. Practice whiteboard architecture - translate your consulting presentation skills to technical diagramming
5. Learn Infrastructure as Code basics - enough Terraform to understand and discuss, not necessarily to write production modules


## Timeline

2-3 months of focused learning on cloud platforms and architecture patterns is enough to make the transition. Your consulting skills accelerate the timeline because you already know how to learn structured frameworks quickly and apply them in client contexts. The main gap is hands-on technical credibility.


## Your Advantage

You can close the client communication gap that most SAs struggle with. Understanding how to run a discovery session, present options with clear trade-offs, manage stakeholder expectations, and build long-term client relationships - these are skills that technically deep SAs often lack. When you walk into a customer engagement, you know how to structure the conversation, identify the real requirements behind the stated ones, and deliver recommendations that executives can act on.
